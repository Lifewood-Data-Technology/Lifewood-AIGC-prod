# Deseret 项目内部制作留档与接手设计

> **历史设计稿。** 本文记录实施前的设计与决定。交叉审核后已有修正，以[现行说明](../../DESERET_PRODUCTION_CONTINUITY_20261121.md)为准，主要包括：
> - 逐镜明确确认留档，确认只在当前一轮有效，不再“按任务默认选最新”；
> - 剪辑师的候选和登记受 `productionReadableVersionQuery` 约束；
> - 工程文件按真实目录判断，写事务复核；
> - 计划交接按 ID 选用留档并复核；
> - 批量换剪辑师只取转出人本人的检查点。

适用范围为 AIGC 中与 Deseret 对接的制作任务。本文描述拟实施的业务规则，不能作为已上线说明。

## 目标

上任剪辑师临时调走时，接手人应能在公司平台找到对应视频的可编辑工程、已有素材和下一步工作，实际打开并续作。出版社收到的分镜、成片和其他既有获准审阅内容保持原有对外范围。历史工程、脚本、日报和上轮已完成的逐镜简化继续保留。

## 已有能力与差距

- 工作区已提供工程、脚本、图片、视频、配音和音乐分类，日报保存工作内容、附件版本、下一步。现有“完整”可以来自一条没有工程附件的日报。参见 `lib/production-files.ts`、`db/production-workspace.ts`。
- 单镜内部送审和负责人整轮对外发布是两个入口。发布端验证实际视频版本、所属语言任务、质检及存储。当前没有固定本轮具体采用的内部工程版本。参见 `db/deseret-integration.ts`、`db/deseret-integration-jobs.ts`。
- 计划交接已有检查点，应急交接已有风险说明。批量改派另走负责人确认路径，可用该任务最近一次记录并直接标记已接手。参见 `db/backend.ts` 的批量分配、交接发起和接手处理。
- AIGC 内部文件有独立读取鉴权。工程留档需要确保新负责人能通过正常入口读取获交接的文件版本，同时保留原有项目、角色和任务的数据隔离。

## 方案选择

沿用现有“制作文件 → 日报/检查点 → 交接资料”，给每一轮送审关联内部的固定版本。逐镜强制重传工程或粘贴脚本会产生大量重复；只保存日报文字与 MP4 无法复原剪辑时间线。无需另建一套上传工具或制作日志。

## 三个操作入口

1. **当日收工**。在 Deseret 任务的日报中，记录做到了哪里、下一步或已完成，并在有制作进展时保存或选用本次可续作的编辑工程版本。脚本或素材准备阶段尚未产生剪辑时间线时，当日可以关联实际在做的可编辑脚本、分镜表或源素材，保留当日进展；不把它自动认作整轮成片的可编辑工程。工程未变化时可明确沿用已存版本。关联实际用到的脚本、素材、音轨、字幕等，无此类素材不补空文件。同一工程内含的素材无需另传一遍。仅记录等反馈等无制作进展的日子，可照常提交日报，不计为新的可续作版本。以剪辑师的明确选择判断，百分比不用于推断有无工作。规则约束保存动作，不新增每日强制打卡、催办或自动代写。
2. **分镜整轮、成片整轮送审**。单个分镜内部送质检继续使用视频和时长。负责人正式发布时查看本轮每个参与的语言任务及视频，确认与之对应的可续作版本，并把关联随包版本固定保存。同一来源可供多镜头复用。多语言、多剪辑师的任务分别检查，不以整个项目最近上传的一个工程代替。新一轮或返修可明确沿用未改的工程或选择新版本，不回写上一轮。历史已发包不补造关联，旧事件重投沿用原有回执。
3. **调动与接手**。计划交接关联移交人本任务的有效工程、预览/已存输出、实际引用素材和工作说明。接手人能从交接页打开或下载允许读取的准确版本，并记录“工程能打开、依赖素材可用、知道从哪里继续”或具体缺项。确认基于人的实际操作，系统不通过扩展名或点击下载宣称软件已打开工程。负责人批量调动同样记录验证状态，不能用负责人调动代替接手人的核实；首次分配、纯质检员调动、普通项目维持既有规则。

## 经代码与实施审查补充的口径

建议将以下规则一并作为本次迭代的业务边界：

- 日报与资料齐备分开计算。有进展却缺少有效源文件时，允许正式提交带缺项的日报，保留实际进度和下一步；负责人发布下一轮时仍须补齐。仅有准备工作的日期可关联实际可编辑文稿或素材，不要求制造空剪辑工程。
- 计划调动按已开始的制作阶段验收。若确实处于准备阶段，新的负责人可凭当前可编辑材料和说明正常接手；尚未产生的预览或时间线标明原因。已有剪辑成果时，预览不能替代工程。接手人无法继续时登记缺项。
- 服务端目前在待质检及出版社审阅期限制工作区写入。建议允许当前剪辑师在这些阶段补记内部日报、正式登记内部留档；保持对已送视频、审核决定、已冻结包及其他角色的原有锁定。已暂停、终止、交付、归档状态不因本次变更重新开放。
- 审阅包沿用现有批次规则。一个整轮中每个场景及其视频版本都要能定位到对应任务和内部来源，不自动把“最近上传”当作这一版视频的来源。发现无法唯一关联时显示缺项；可明确选用同任务的正式来源。对“已有视频提交内部质检”也保存提交记录。跨多日多次上传的新工程按版本记录，禁止用同名文件推断替换对象。
- 负责人批量改派仍可做人员安排，但仅改派不能自动生成接手人的核验结果。维持未确认交接时的现行质检限制。已确认“收到资料”但仍有缺项的紧急交接，其后是否能送内部质检，由下面的例外规则决定。
- 内部质检员继续使用审核材料，未获授权的个人工作记录、未正式确认上传和其他语言任务的草稿不因改派而开放。负责人可在现有合法权限内关联已正式登记、能按版本追溯的本任务资料；不恢复前任私有草稿。缺失就显示缺失。
- 沿用检查点和送审材料的版本保护，为新增的内部引用补全同等保护。发布关联、撤回、改派和旧链接均纳入验收。

## 待确认的例外

原剪辑师突然离开且工程缺失时，沿用紧急改派、记录缺项。建议允许接手人内部补做、送内部质检，把资料标为待补；新一轮对外提交前补齐工程。另一选择是保留改派和资料读取，但缺件期间禁止内部送质检。无论选择哪种，界面均应准确区分“已调动”“资料待补”“接手人已验过”，原有历史如实标明未记录。

## 数据与权限

工程以内部不可变文件版本为单位。原生工程或可打包续作的源文件沿现有工程分类和上传规则保存；仅有预览、普通脚本文字或个人工作台链接不能替代工程。使用方可重新引用已有版本，不需要重新上传。平台核对任务、角色、正式登记、文件类型与可用状态，不读取整个文件来判断内容。已删、回收、被撤销访问、尚在暂存及其他任务的文件不能冒充有效留档。已引用版本沿用既有保留规则，若合法删除或撤权，显示实际缺项，不能用更新版本悄悄替换。

内部快照与对外文件清单分开保存。内部工程、脚本、账号、路径、工作说明和缺项不得被序列化到对外响应、文件转运队列、签名下载或历史重投正文。继续使用现有鉴权和直传。写入时复核状态和版本；整轮、交接和改派的快照与对应业务动作原子保存。重复提交不产生重复记录；并发替换、删文件或换人时拒绝陈旧确认。旧记录允许查看，升级不推断它们已具备交接条件，不改写旧包、不批量清理历史。

## 验收

- 合成剪辑师甲上传一次工程，记录镜头 1–8 的工作和剩余修改；乙接手后能按准确版本找到工程、预览和本轮实际素材。工程更新到 v2 后，旧包仍指向 v1。
- 没有旁白的项目不要求音频；日报保存“等反馈”不会覆盖已存工程。有进展但缺少可用源文件时，能保存已有工作或看到明确缺项，不会误标资料齐全。
- 两个语言任务的分镜共用一轮，一个任务缺工程时能定位具体任务；一个工程可覆盖同任务多个镜头。返修、成片、更正、历史重投、重复点击和并发修改有回归覆盖。
- 测试计划交接、紧急缺件、批量换剪辑师、单独换质检员、已离任账号和无关人员；覆盖正常读取与拒绝读取。检查人员完成调动与资料完成验证是两个可区分的结果。
- 使用合成保密标记检查对外包、媒体清单与重投；中英文走过日报、发布、接手和缺项提示。禁止访问真实业务库、账号和存储来验收。提交、推送和部署遵守本轮授权。

## 实施决定（2026-11-21，用户确认实施后；历史记录，现行规则见[现行说明](../../DESERET_PRODUCTION_CONTINUITY_20261121.md)）

用户新增硬约束：工作日报整体保持原状。不强制填写、上传或关联，不改字段、开放时段、入口和旧数据。以下为据此确定的实现口径，取代上文与日报相关的建议（如“当日收工”在日报中保存工程、“允许在待质检和审阅期补记日报”）。

- **内部留档与日报无关。** 新增 Deseret 任务的“内部留档”，每次登记生成一个不可变的版本号（任务内递增）。
  - 内容：一个必选工程文件版本（本任务 `03.project` 工程分类的正式版本），以及可选的预览视频、本任务素材版本和下一步说明。
  - 登记方式有两种：选择本任务已正式登记的文件；或经既有暂存和正式确认上传，在同一事务中保存文件并登记留档。
  - 留档不读取文件内容判断有效性；不接受暂存中、已删除、其他任务或素材库文件。
- **何时可以登记。** 当前剪辑师可为自己的任务登记，项目负责人可为本项目任何任务登记。
  - 质检中和出版社审阅期间也可以登记；已暂停、已交付、已归档、已终止的任务不行。
  - 单镜送质检、日报和普通项目不变。
- **发布门禁。** 负责人发布整轮分镜或成片时，须为包内每个镜头（每个实际任务的视频）指定同一任务的有效留档。同一份留档可覆盖同任务多个镜头。
  - 绑定与发布原子保存，版本固定。之后再登记的留档不会改写旧包。
  - 以下情况挡发布：缺留档、留档失效（引用版本被删或不在本任务）、任务有待确认交接、交接核验为“缺项”而所选留档早于该交接。
  - 负责人可在发布处直接为缺项任务登记留档。
  - 历史包不补造绑定；旧事件重投沿用原回执。
- **交接（仅 Deseret 项目的剪辑师调动）。**
  - 计划交接：无完整日报时，可用本任务的有效留档代替。
  - 计划交接、应急交接、负责人批量换剪辑师都会记录一条交接核验：关联当时最新的有效留档（可为空），状态为“待核验”。
  - 接手人自行登记“已核验可续作”或“缺项及说明”。人员安排与接手核验是两个独立结果。
  - 应急缺件时，可以接手并在内部补做、送质检；补登留档前不能对外发布。
  - 纯质检员调动、首次分配、普通项目保持原状。
- **权限。**
  - 任务的现任剪辑师可读取本任务任何留档引用的版本，因此链式换人后仍能拿到全部留档资料。
  - 质检员沿用审核材料，不因留档或改派获得工程读取。
  - 负责人沿用项目权限。
  - 留档引用的版本纳入删除保护。
- **外发隔离。** 留档、留档文件引用、发布绑定和交接核验存在四张内部表中（文件引用单独成表，不存 JSON），不进入状态 JSON、对外事件、文件转运任务或重投正文。
- **持久结构。** 新增迁移 `0010-deseret-production-archives.sql`，并同步迁移清单、结构契约、版本校验、业务删除、演示清理和部署说明。
